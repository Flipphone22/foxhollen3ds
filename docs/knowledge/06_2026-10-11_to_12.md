## 2. Rejected or failed experiments (do not repeat)

**Shadow CPU and GPU work** (the gate is 0.5ms CPU for the whole shadow feature):
- **Shadow range BVH V1/V2 (L19800-19856).** V1 added 1.54ms of CPU. It cut indices 23% but raised the draw count from 46475 to 82194. V2 (one envelope per draw) added 0.61ms and saved only 5.1% of indices. The cause is poor contiguous spatial locality. Do not try smaller leaves; this needs a different representation.
- **Spatial Morton shadow ordering V1/V2 (L19746-19764).** Indices fell 45.8%, but CPU rose by 0.67ms (V1) and 0.34ms (V2).
- **Spatial+camera V3 (L19684-19729).** Draws fell 26% and indices 52%, but CPU rose by 0.26ms.
- **Query context V4 (L19619).** Saved only 0.018ms and stayed 0.24ms over base. Do not tune visible-mesh keys any further.
- **Camera-mask shadow candidate (L19868-19878).** Saved only 0.028ms. Not promoted.
- **Shadow preflight `0a3e70fd1617` (L19470-19494).** It skipped 378 empty masks but zero geometric captures, and CPU stayed effectively unchanged. Do not request hardware for it.
- **Rigid actor visibility V2/V3 (L19504-19563).** It touched only about 0.35% of actor index work, and render CPU rose by 0.04-0.08ms. Do not spend more turns micro-tuning per-draw rigid checks for less than 1% of GPU work.
- **Source-order gap prototype and live-bound prototype (L19585-19606).** These gave a further 8.3% and 8.2% point reduction. Neither was wired in, because the cost/benefit tradeoff was not accepted.
- **Direct shadow world transforms V7 (L20290-20355).** Removing the camera inverse round trip saved only 0.013ms. This line of work is now exhausted. The whole feature still costs 0.72ms against the 0.5ms budget.
- **Shadow range V4 (L20444)** added 0.054ms. **Range cache V5** saved 0.047ms (L20377).

**Shader banks (L20238-20288).**
- V1, a shared actor/HUD/shadow bank, increased command bytes by 3.57% with no gain.
- V2 failed to link at 556 instructions. The 489 count omitted 67 particle-helper instructions, and the strict below-512 guard caught it.
- V3 (main 500 + auxiliary 129) increased command bytes by 1.67% with negligible CPU change.

## 3. Known open bugs

- **Sky flat on hardware (L20044-20060, L21004-21047).** On physical New3DS the full cloud shader renders flat, zero-variance blue. The oracle and texture rectangles render detailed clouds, while no-cull, no-depth, scaled clip and RGBA8 variants all stay flat. The fault is narrowed to the shader/output path and resembles the C-menu direct-UV defect. Cloud textures are 1196 (I8, 0x88d) and 1199 (IA8, 0x88c). In the emulator, the submitted geometry and UVs exactly match source (L21099). The direct-UV cloud shader exists, but the UV probe (`dabc37ff5e71` at `/3ds/foxhollow-sky-uv/`) still awaits a NEW user run. Collections kept returning the stale log from the first probe (source `4ed8c2d99fcfff64`), cause unknown (L19858-19866, L19931-19947). The sky is NOT physically fixed.
- **C-menu shared-shader defect.** The full/shared 511-instruction shader drew only 256 pixels (the top strip) on hardware. A direct ordinary UV restores it, and the 43-instruction UI shader fix was accepted (L22361-22401). The exact shared temporary/control-flow cause is unknown. Do NOT apply direct UV globally over the fur/specular paths.
- **Shadow feature CPU cost** is 0.729ms against the 0.5ms gate, still failing (L19653-19654).
- **Shadow parity gaps:**
  - Dynamic and object receivers are missing.
  - Finite-volume behavior, softness and self-shadow are not implemented.
  - The strict pixel gate on hardware gives 231 edge pixels against a limit of 100 (L21307-21309).
  - The original authored-filter counterexample means the native AABB must keep authored constraints (L20637-20640).
  - Missing receivers on Old were caused by scratch admission and fixed in V6 (L20386-20402).
- **Fur.** It looks underwhelming compared with the original even with SOURCE FUR on. Wind, projected lighting and the exact diffuse map are absent. The masked-fur path already uses all 3 samplers (noise, base, coverage) (L22017-22020).
- **Cave haze.** It varies between runs and depends on particles. It is not proof that mist is broken. Do not remove it or change the alpha (L20842-20851, L22701-22706).
- **Earlier hardware fault.** Turning SPECULAR ON fixed the white Arwing and invisible trees, while OFF brought them back (L22656). The root cause was never established, and a later report says it seemed fixed.
- **Water ripples and wakes** need the source reflection/distortion materials. Do not swap in plain quads and call it parity (L20788).
- **Six post-light C2-alpha declarations** remain absent (L20129).
- **Hardware performance.** Old3DS was seen at 80-90ms frames with about 20ms of GPU time (L21229). New3DS was seen at 20.5 FPS in the cave with SHADOW ON (L21782). Targets are 60 FPS (minimum 30) on New and about 20 on Old (L20162).

## 4. Architecture and engine facts

- **Shader budget.** The main scene program is 511 instructions under a strict 512 guard. Other programs:
  - UI: 43
  - Fur: 216 (wind variant 327)
  - Material: 304
  - Layered: 304
  - Cloud: 183
  - Shadow point: 133 (106 VS + 27 GS)
  - Lightning: 66
  - Weather: 26 and 23
  - Particles: share the 511 program

  The hardware-proven shadow set is 73 instructions in one shared DVLP: UI43 caster + 9-instruction clear + 21-instruction projector (L21298).
- **Azahar is not a physical float24 model.** Its Pica::Float retains float32, so "float24 VM" tests are not physical-precision proof (L22216).
- **DisplayTransfer** needs a width of at least 64 on hardware; Azahar accepts invalid sizes (L21670).
- **Stock citro3d `C3D_TexBind(unit, NULL)`** dereferences NULL. The patched `texture.o` (citro3d_null_texture.py) is required, with an 18-case ARM gate (L22433-22442).
- **Shadow image owner:** 3x128x128 RGB565 = 98304B VRAM (L21902). The point plan uses 32B per triangle. Caps are 1MiB linear, 256KiB metadata and 2MiB scratch (L20524).
- **Original game shadows** project finite receivers with a depth ramp, multiplicative blend and 3/4 alpha (L21957). The source picks marked collision faces (`collectShadowTrackTriangles`), not visible triangles. The collision data has 1267 static blocks and 477273 eligible triangles. The source block transform already includes collisionYOffset (L21517).
- **World geometry:** 1259 packets, 977666 triangles, of which 15853 are duplicate oriented triangles (L21814).
- **Vertex-cache audit:** a meshoptimizer reorder would cut FIFO16 misses by 33%. Do not reorder blindly, because blend, equal-depth and source order matter (L19442-19453).
- **Original updateHeavyFogTexture** CPU-rasterized 4096B whenever the height selector changed. The producer is now replaced (L20963).
- **Original drawGlow** calls `_gxSetFogParams`. The native GS particle owner had omitted distance fog (L20813).
- **The New3DS second core (core2) is used by audio.** Never assume 2 free graphics cores.
- **Memory peaks:**

  | Console | Heap | Linear free | VRAM free | Process |

  | New | about 48.4-56.6M of 71303168 | about 16-18.4M of 25165824 | 4723712 | about 103.3M of 130023424 |

## 5. Tooling and workflow

- **Isolated snapshot builders.** Each builder snapshots the full source set (439-458 files) plus `libgame.a` and restores WIP and the archive in a finally block. Never blind-build the worktree: it holds six unrelated VRAM files and finite-shadow WIP. Many pure patches are already applied to WIP, so never double-apply them. Shared Old80/New124 CIA profiles are verified on every build.
- **native_shadow_gate.py.** Mandatory for shadow-ON cave runs. It rejects runs with missing plans (L20389).
- **compress_completed_run_elf.py.** Compresses older ELFs with lossless NTFS compression plus SHA checks when the disk-space preflight refuses a run. It never deletes anything. Free disk space on C: is tight (about 550-680MB).
- **Headless runs.** `run_console_headless.py` (supports `--capture-every`) and cave/moving/intro fixtures. Captures are inspected, but they are not pixel-equivalence evidence.
- **Hardware probes:**
  - Shadow cave probe and sky GPU probe.
  - Collectors: `collect_sky_gpu_probe.py`, `collect_shadow_cave_probe.py`, `collect_cmenu_gpu_probe.py`.
  - Analysis: `check_sky_probe_installation --app foxhollow-sky-uv`.
  - Probes auto-exit; the user then reopens ftpd.
- **Deployment.** Uses staged upload plus full-byte readback (console-settings-update). Console IPs are New new223 and Old .229. `finalize_visual_settings_update.py` handles the Old upload.
- **Fixture caveat.** The startup default mask 16385 does not log a change. Settings fixtures must use FNV, not CRC32.
