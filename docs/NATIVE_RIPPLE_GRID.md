# Prepared procedural ripple inputs

14 October local prototype. Not connected to gameplay, built into a new app,
deployed, or performance-accepted.

The original `allocLotsOfTextures` generates the64x64 RGB5A3 bump texture once.
`setupReflectionBumpDistortTev` uses alpha/blue displacement and green coverage;
the authored0x56 texture is not its actual bump source. Ripple quads use UV
endpoints127/128. Their indirect matrix scales are0.125 and0.0625, half the
wake scales. These are distinct source requirements, not interchangeable masks.

The shared load-time compiler now has a ripple entry accepting the original
generated bytes. It samples A/B offsets into the existing16-byte padded SHORT4
vertex format and prunes only cells whose entire green bilinear support is zero.
Geometry UV remains0..1; a future owner must apply127/128 to its mask uniforms.
The31-instruction grid shader can consume the prepared format unchanged. No
per-frame texture sampling, CPU vertex generation, worker or shipped game pixels
has been added. The game still owns generation and simulation; neither changed.

The compiler check extracts the actual original generator block and original
ported cosine function, with constants decoded from `game_data_gen.c`. It checks
all four grid levels against independently decoded tiled RGB5A3 samples and
coverage. ASan/UBSan passes; maximum sample rounding error is0.03125 byte levels.
Synthetic cases distinguish zero alpha from zero green, and capacity failures
leave outputs untouched. Strict ARM compilation passes. The shared internal
compaction function reserves8896 stack bytes excluding callers, only at load.
Existing wake source tests still return identical counts and zero sample error.

## Attribute-aware reduction and resident owner candidate

The pinned meshoptimizer kernel already used by on-device installation now
has a load-only ripple adapter, `pica_ripple_reduce.c`. It retains exact surviving
SHORT4 vertices, fixes the existing coverage boundary, and reduces index topology
using both displacement channels as attributes. The compiler's source pixels,
game simulation and original model assets are unchanged. This is not a per-frame
CPU simplifier and is not yet called by the gameplay renderer.

Five candidate tolerances were compared using independent triangle raster
sampling of the compiled data. The selected development candidate uses0.002:
6854 becomes3054 triangles per pass, a55.4% reduction; prepared storage is44820B
(44928B at the owner's128-byte alignment). At128x64 with varying projective Q,
mean RGB error against source offsets changes1.014→1.410 and p956.196→7.947.
The maximum remains93.048. The inspected contact sheet retains ring detail.
This is a measured approximation, not pixel equivalence or original-game visual
acceptance. More aggressive1590/1030-triangle candidates have higher error and
have not been selected. No physical GPU/FPS improvement has been established.

The same approach is less useful for the wake's noisier map: the0.002 candidate
only reduces2376→2196 triangles. Its0.005/0.01 candidates increase p95 error to
10.08/15.37. The wake owner therefore keeps its existing mesh; this is not a
blanket decimation policy for unrelated assets.

`test_pica_ripple_reduce.py` compiles the actual C adapter with ASan/UBSan and
links the pinned bounded C++ kernel. Output triangles and all attributes match
the image-tested candidate exactly. All three allocation failures preserve the
original buffers and result; malformed input is rejected before allocation.
The adapter also compiles and links with the real ARM SDK. Its local stack is
272B excluding callees. The actual fixture's temporary reservation is1294875B,
including the full1MiB arena, not just its926000B used prefix. The owner also
holds120396B of compiler input during reduction, totaling1415271B temporary
reservation before upload. Resident budget and actual allocation peaks still
need runtime checks. No game-derived prepared data is shipped.

The initial topology audit rejected collinear zero-area triangles returned by
the pinned simplifier. Inspection found no negative triangles or changed area.
The audit now counts zero-area submissions honestly while still rejecting
reversed winding and requiring the exact original oriented boundary and area.
The selected candidate contains one zero-area triangle. It has not been silently
removed from the GPU workload count.

`pica_ripple_owner_patch.py` extends only an isolated water-grid snapshot with
two resident plans. The two families share their31-instruction GPU program and
ordered scene capture, but retain separate geometry, masks, UV scale and
precompiled material tables. Ripple coverage selects green, mask UV includes
127/128, and indirect scale is half the wake's. Load failure rolls back the
optional plan; release/shutdown retain the existing retirement boundary.
Peak linear telemetry counts both plans. No per-draw allocation or mesh rebuild
was introduced. This adapts the pinned Melee resource-owner discipline, rather
than reusing its renderer.

The owner compiles with strict real-SDK warnings after fixing one indentation
warning (retained in `compiler-v1-failed.log`). This is only compile acceptance:
two-plan delayed-reader/lifetime tests, game-state adapter, toggle policy,
replay build/linking, GPU captures and performance gates remain open. The current
32-bit graphics option word is full; choose an explicit compatible UI/replay
policy before wiring another independent toggle. Do not silently reuse another
effect's bit. No new app or console deployment follows from this prototype.

Evidence: `ripple-grid-reduction/{result,pixels}.json`, its `pixel-comparison.png`,
`wake-grid-reduction/{result,pixels}.json`, `ripple-reduce-owner-test/result.json`,
and `ripple-owner-check/result.json`.

## Game integration and independent toggle, 14 October

The two-plan owner is now linked into the local replay candidate. Its actual
owner/compiler/reducer passes 16 modeled delayed-reader lifecycles, alternating
wake/ripple materials, five admission failures, independent reloads and final
retirement. Missing retirement, green coverage, 127/128 UV scaling and half-size
indirect offsets each cause the regression to fail. Peak resident geometry for
both plans is 81,920 B. This models SDK boundaries; it does not establish
physical cache behavior or GPU throughput.

The original game19 adapter loads the original generated bump texture and
consumes live ripple poses, opacity and `gReflectionBumpKColor`. It preserves
source ordering (ripples, splashes, drops, wakes), pool updates and random calls.
The actual generated adapter passes independent toggles, empty/unready pools,
capture failure and one-shared-capture checks; eight original simulation/spawn
function bodies remain identical. No per-frame CPU vertices or new worker.

The original 32-bit option word is full. A second word adds `RIPPLES` without
renumbering existing bits. All four presets leave it off. FHGRAPH5 settings
retain two checksummed slots and read older versions with extra effects off.
Replay recipes may specify `EFFECTS 1`; old recipes default to zero. Recording
snapshots this word at its start, and replay comparison rejects mismatched
effect words. The bottom screen still redraws only on changes. Settings/parser,
recording, menu-lock and idle-update host checks pass. Plans are prepared at
load even when disabled; disabling skips the per-frame capture/pose/draw work,
not this documented resident and load-time cost.

The first game run (`ripple-v1-on-new`) rejected the effect with status12:
both plans loaded, but the shared capture still required WAKES to be enabled.
No ripple was drawn, so that run is **not** visual acceptance. The corrected
capture admits either word, rejects only requested effects on allocation
failure, and shares one capture per frame. Actual-function tests cover 32
toggle/availability combinations and nine failures; the old gate fails the test.
The original failure is retained. The corrected v2 build keeps the v1 game
archive and all 18 shader programs unchanged, with Old80/New124 CIA profiles.

## Actual GPU image check, 14 October

`test_ripple_device.py` links the archived two-plan owner, original source-mask
compiler, bounded reducer, real SDK and the unchanged31-instruction program.
Eight silent Azahar cases force a command split and different program/material
before each of16 draws. They cover both reflection channels, mixed colour,
opacity, heavy-fog mixing, zero opacity, equivalent projective Q and foreground
occlusion. This fixture draws a synthetic captured image using private,
source-generated mask pixels; it is not an original-game screenshot comparison.

The first build attempt stopped before launching because a dependency resolved
outside the isolated snapshot. The corrected fixture copies the pinned meshopt
files into that snapshot. Its15.03-second run completed all cases and exited.
Initial image validation failed because the oracle used RGB8 colour constants
for an actual RGB565 capture. The correction applies the pinned format's
truncate/bit-replicate conversion; neither renderer nor thresholds changed.
Existing captures were revalidated without another boot. Both failures remain
in `artifacts/native-ripple-device/v1` and `v2/result.json`.

Across75,322 evaluated pixels per case, maximum mean channel error is0.4253/255,
maximum p99 error1.5876/255, maximum individual error2.1144/255. Equivalent-Q
images are identical after excluding the fixture marker. Zero-opacity and
occluded images exactly retain the background. Actual/expected/error images
were inspected. Altering the independent reference to omit offsets, use wake
strength, or omit127/128 UV scaling fails the same threshold; selecting alpha
instead of green fails source-coverage admission before pixel comparison.

Evidence: `v2/post-validation.json`, `v2/ripple-pixels.json` and
`v2/equation-mutants/result.json`. This validates the prepared approximation's
GPU sampling, blending and state handoff in Azahar, not hardware throughput,
exact GX filtered bump-alpha quantization, or live source-game parity. A compiler
enum-size warning in the fixture was reviewed: the reducer boundary carries
integer/float/pointer data, not enum-sized structures. The native SDK-facing
owner must retain devkitARM's short-enum ABI, as the actual platform build does;
the game/reducer uses32-bit enums across a scalar-only interface. An attempted
fixture-wide32-bit override was incorrect and has been removed. The retained
v2 pixels use the original SDK-compatible command.
