# Direct image decoding into unpublished PICA storage

The Old palace replay of movie-overlap-v1 failed at retrace 915 while loading a 244x48 format-5 HUD image. Failure-only instrumentation reproduced it: staging allocation was rejected at heap 41,333,632 / 49,283,072 bytes, stack reserve 524,288 bytes, request 65,536 bytes. Material use was 166,292 / 524,288 bytes and free linear memory 4,343,808 bytes. The staging request crossed the normal heap 85% admission limit. This is distinct from physical dinosaur-rescue crash198, which remains unresolved.

The replacement allocates an unpublished C3D texture and decodes directly into its linear storage. Exact converted-byte deduplication remains: duplicates increment the resident reference and delete the unpublished candidate; unique images transfer ownership to the resident slot. No heap staging or final memcpy remains. The image cap stays 4 MiB and the 15% linear reserve is checked both before and after tentative allocation. Unique-image admission still checks the resident cap. Failed conversion, allocation, reserve or admission frees the unpublished candidate. No sampler is exposed before the existing cache flush. Existing release/fence ownership is unchanged.

Pinned Melee texture_storage.h and texture_repack.h preserve source precision and tiled conversion. texture_vram.h documents hardware failure from dynamic promotion; this change does not introduce promotion or VRAM writes. Citro3d texture.c confirms ordinary C3D_TexInit uses linearAlloc and initializes all texture metadata. Unlike the old calloc buffer, SDK storage is uninitialized; the retained converter writes every output texel, including padding. Actual-game validation is required in addition to mocked owner tests.

The host ASan/UBSan test extracts the actual archived acquisition function. It reproduces old staging refusal and checks direct decode, full output bytes, exact dedup, publication flush, resident-cap rejection, linear reserve and cleanup. Its SDK allocation and converter are mocks: it does not establish physical GPU correctness or real-game pixel parity. Game code/archive and all 21 shader programs remain unchanged in the isolated replay build. No physical FPS improvement is claimed.

Evidence: artifacts/research/pica-scene-rewrite/image-direct-decode-test/result.json; artifacts/native/image-failure-v1-on-old; isolated image-direct-decode-v1 build family. Runtime acceptance is recorded separately after the bounded palace test.

The repaired Old palace replay completed in 55.67 host seconds, with replay status1, saves unchanged, drained logs and owned emulator exit. Captures1200/1410 were inspected. Sampled normal heap peak41,332,728/49,283,072; linear minimum free4,301,312/12,582,912; VRAM free4,723,712; main stack73,008/524,288; process69,541,888/83,886,080. These periodic observations do not establish transient peaks; the allocation checks enforce the reserve. The previous exact build failed before completing this route, so no comparative FPS gain is established. The existing replay uses a prepared asset fixture, not the current normal app's on-device conversion package.

Tradeoff: duplicate unprepared images now briefly need a candidate allocation in linear RAM before exact byte comparison. Previously the temporary image occupied normal RAM. The candidate is bounded by the existing 4 MiB image-size ceiling and linear reserve, and is immediately deleted on a duplicate. Unique images avoid simultaneous heap and linear copies entirely. No published texture is modified or repurposed.
