# Bounded short copies in movie decoding

The eight-frame retained cockpit profile expands 42,958 direct copy calls through __aeabi_memcpy to fh_lz4_block. This identifies a decoder caller, not copied bytes or cycle attribution. A separate read-only audit of nine prepared RGB8 movie frames validates their CRCs and finds 25,531 zero-byte literal copies, 11,957 four-byte matches, 10,767 six-byte matches and 6,086 five-byte matches. These representative frame IDs are not asserted to match the captured cockpit frames.

The candidate retains the bounded LZ4 parser and disjoint doubling-match algorithm, replacing copies of zero through eight bytes with inline fixed byte accesses. Larger copies use the existing SDK memcpy. No unaligned word loads, wild copies, dictionary, per-frame allocations or omitted integrity checks are introduced. Source frame advancement, simulation, audio and rendering are unchanged.

39,784 ASan/UBSan cases compare exact decoded bytes, untouched output tails and acceptance/rejection against the archived decoder, with real packets, truncated prefixes and four output alignments. Full packets match their original CRCs. Clang18 ARM11 wrappers linked against SDK memcpy reduce aggregate instruction encounters on nine packets, with a small regression on the final nearly empty frame. These are instruction counts, not cycles or FPS; actual linked function verification and gameplay are separate gates.

The first broad header candidate failed the unchanged-installation-recipe assertion. It is retained as rejected v1 with exact source hashes and binaries. v2 limits the new helper/header to the THP movie consumer through the existing adapter. Generic asset decoding, installer source/recipes, original assets and saved progress stay unchanged. No automatic conversion invalidation is accepted for this runtime-only change.

Actual linked thp_shim.c decoder execution reproduces all nine standalone ARM counts exactly: aggregate 9,303,042 to 8,263,768 encounters (-11.17%); last-frame168,244 to168,986 (+0.44%). Function selection uses ELF STT_FILE ownership because four generic decoders share the old static name. This test uses complete archived app ELFs, not recompiled substitutes. The general asset decoders retain their old header.
